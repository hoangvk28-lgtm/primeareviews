  seo.ts                   buildMetadata(): always use it, never hand-build Metadata

  types.ts                 PrimeaGuide / PrimeaProduct shapes (source of truth for guide JSON)
  guides.ts                getGuide(), getAllListings(), getByCategory()
data/
  categories.ts

  guides-index.generated.ts  AUTO-GENERATED by `npm run index`, never hand-edit
scripts/

## 4. SEO Metadata Rules

- Always `buildMetadata({ title, description, path, image, type })`. It appends ` | Primea` (9 chars). Never append it yourself.
- **metaTitle must contain "Ranked & Reviewed" and be ≤ 51 characters** (renders ≤ 60). Patterns: `Best Dual Monitor Arms 2026: Ranked & Reviewed`, `Robot Vacuums for Rugs: Ranked & Reviewed (2026)`. Shorten the product phrase rather than drop the label. `npm run check` enforces this; count, do not eyeball.
- **h1:** `The N Best <Product> of 2026, Ranked & Reviewed` or a close variant.
- **metaDescription:** 120–160 characters, opens with `Ranked and reviewed by Primea:`, unique per guide.
- Canonicals come from `buildMetadata`; no trailing slashes.

## 6. Affiliate Compliance

- All Amazon links: `target="_blank" rel="noopener noreferrer sponsored"` and `?tag=primeareviews-amz-20`.
- The tag is hardcoded in **three** places that must always agree: `AMAZON_TAG` in `lib/site.ts`, the `TAG` constant in `scripts/rewrite-guides.mjs` (it goes into the rewrite prompt), and the assertion in `scripts/check-guides.mjs`. If the tag ever changes, update all three in the same commit, then run `grep -rn "tag=" data/guides | grep -v primeareviews-amz-20` to catch guides written with the previous tag. A batch generated while `rewrite-guides.mjs` still holds the old tag will produce hundreds of `check` failures; fix it with a sed over `data/guides/`, not by relaxing the check.
- Disclosure note sits under every guide header (already in `GuidePage.tsx`); `/affiliate-disclosure` linked in the footer.
- **Never display Amazon star ratings or review counts**, in UI or prose.
- **Never write exact prices** (`$23.99`). Use buckets ("under $50", "$50 to $100"). The `price` field may exist in JSON for internal use but must never render.
- Product images: `m.media-amazon.com` URLs carried over from source data only.

## 7. Editorial Rules

### 7.1 Voice
Primea writes as a senior product reviewer with years in the category: confident, decisive, specific. Short paragraphs, real numbers, clear "buy this, skip that" calls.

### 7.2 "Ranked & Reviewed", and the line we do not cross
Primea guides are genuinely **ranked and reviewed**: our editors research each product (spec sheets, manuals, warranties, certifications, owner feedback), score it on the Primea framework, and rank it. That is what the label claims, and it is true.

Primea guides **do not claim physical testing** unless a product was actually tested in person. Never write "we tested", "we tried", "hands-on", "in our lab", "we measured", "after N weeks of use", "our testing", "tested by". `npm run check` fails on these. If the team physically tests a product in future (with own photos and measurements), add a `tested` field to that guide and only then use testing language for that product.

### 7.3 Uniqueness: rewriting sister-site content
Products and article ideas may come from DeskFinds/WorthRated. **Text may not.** For each guide:
- New title wording, new opening angle, new structure and section headings, own award labels, own ranking judgment.
- Facts (specs, capacities, dimensions) are carried over; sentences are not.
- `node scripts/check-duplicates.mjs` must pass: zero 10-word runs copied from the source guide, zero identical product lineups between Primea guides, zero phrases repeated across 3+ Primea guides.
- If the source data looks wrong (it sometimes is, e.g. mislabeled spring types), drop the claim; never repeat a doubtful fact.

### 7.4 Required guide shape (`lib/types.ts`, enforced by `npm run check`)
- `products`: 5+ items, sorted by `score` descending, unique scores 78–96. Each: 3-paragraph `description` (role + specs / ranking tradeoff vs neighbours / who should buy + caveat), one-line `verdict`, 4 `keySpecs`, 4 short `pros` (3–8 words), 2–3 `cons`, `idealFor`, `skipIf`.
- `summary` (3–4 sentences), `intro` (2 paragraphs, original hook).
- `whatMatters`: 5 entries, each: what it is, why it matters concretely, how to verify on a listing.
- `methodology`: 5 category-specific criteria.
- `howToChoose`: exactly 6 sections: By <primary attribute> (table) → By Budget (table, dollar buckets) → A vs B (2 cards + note) → second decision axis (table) → For <use case> Specifically ("Look for" / "In this ranking") → When to Spend More ("Spend more if" / "Save if"). Every recommendation names a product in the guide.
- `faq`: 6 entries (compatibility, common mistake, "worth it over", setup, maintenance/edge case).
- `finalTake`, `related` (3 existing slugs, filled by `link-related.mjs`).
- No em dash or en dash anywhere.

### 7.5 Primea Score (fixed weights, do not change)
| Criterion | Weight |
|---|---|
| Performance | 30% |
| Build & Materials | 20% |
| Everyday Usability | 20% |
| Value | 20% |
| Owner Satisfaction | 10% |

Bands: 92+ Outstanding, 85–91 Excellent, 78–84 Very Good.

## 8. Content Pipeline (batch production)

```bash
node scripts/select-candidates.mjs 1000          # pick sources (skips published slugs, dedupes lineups, caps clusters)
node scripts/rewrite-guides.mjs one <slug>       # spot-check one rewrite synchronously
node scripts/rewrite-guides.mjs submit 0 100     # queue a batch (Message Batches API, 50% cost)
node scripts/rewrite-guides.mjs collect <batch>  # write data/guides/*.json
node scripts/link-related.mjs
npm run index
npm run check && node scripts/check-duplicates.mjs
npm run build
```

- Model: `claude-opus-5-5`. Requires `ANTHROPIC_API_KEY` in the environment (never commit it).
- Run batches in chunks of 100. Fix or delete any guide that fails `check`/`check-duplicates` before committing; re-submit failures.
- Before publishing a batch, open 3 random guides in the browser and read them. Passing scripts is not proof of quality.
